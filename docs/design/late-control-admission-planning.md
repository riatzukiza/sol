## Proposed policy and portable law

A pure decision receives shaped in-flight/terminal facts, control records and pending-turn information, with stable per-session identity/ordering facts supplied from the adapter. It produces an explicit consume, transfer or refuse decision plus intended state updates. No Promise, atom, Node object, Date or AbortController enters the pure namespace; existing host facts are normalized by the adapter. This is Sol-specific control semantics, not another FSM/event ledger or a port of turn-processor internals.

Proposed default for review: normal completion hands undrained controls to fresh serialized turns; failure/abort/refused admission explicitly rejects undelivered controls. Preserve queue order, and explicitly decide how late steering and follow-up interleave without changing existing mid-turn steering priority implicitly. Rejection-only can be selected instead if both kinds' caller-visible behavior is reviewed. The law must account for promise settlement timing and exactly-once ownership: immediately acknowledging a queued control then clearing it cannot satisfy the DoD, and rejecting an already settled promise is ineffectual.

The adapter owns host promises and serial pumping. Define acknowledgement at a reviewed actual consumption/delivery boundary, not mere queue removal. For future accepted controls it must retain the link between control identity, handoff and caller result. Existing current-turn promise settles after post-turn state is final; preserve that ordering. Retain message conversion/content, model/tool configuration, history, events, subscriptions and session serialization. No unreviewed request/response API change is hidden in cleanup.

Actual pinned turn-processor 0ed56aa74a53a1d1e9c2e55ce95451817a7f3a90 loop.cljs 63–78 checks abort before the first drain and again after awaited drains. A pre-existing abort leaves queues undrained; an abort during an awaited drain can return nil after the adapter already removed controls. The current function docstring is not proof of delivery. Preserve the consumed-versus-delivered distinction and test both timings at Sol's boundary. Any required change to the owning loop is separately routed upstream; do not copy its engine into Sol. Avoid infinite retry/new-turn loops after failure, cancellation bypass or merging unrelated messages. No persistence/recovery semantics are inferred from process-local atoms or from the distinct Clio lifecycle feature.
